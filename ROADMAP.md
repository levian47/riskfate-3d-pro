# Riskfate 3D Pro — план розробки

> Тільки фактичний стан 3D Pro. Не переносити виконані завдання, коміти, схеми чи статуси іншого проєкту.

## Поточний стан — 06.11.2026

- **Підтверджено в репозиторії:** створений публічний GitHub-репозиторій `levian47/riskfate-3d-pro`; на початку адаптації були `.gitignore` та мінімальний `README.md`.
- **Документація:** перенесено та адаптовано концепцію ігрових механік, архітектурні принципи, правила 3D-графіки/UI, інструкції Codex і план робіт. Історичні файли документації іншого проєкту видаляються.
- **Не підтверджено тут:** Godot-проєкт, Ninja Demo v7, ігрові сцени, ресурсні моделі, автоматичні перевірки, Web-експорт, GitHub Actions/Pages та успішне тестування на телефоні.
- **Не реалізовано у цьому репозиторії:** сервер MMORPG, синхронізацію, авторизацію, економіку, бойові й прогресійні системи.

## Етап 1 — перенести й стабілізувати технічний 3D-прототип

- [ ] Отримати саме останню виправлену Ninja Demo v7 та звірити її склад, версію Godot і залежності.
- [ ] Додати `project.godot`, сцени, скрипти й необхідні ресурси без зайвих чернеток.
- [ ] Перевірити локальну роботу: рух, колізії, стрибок, атака, ривок (лише якщо останні вже реалізовано).
- [ ] Встановити відтворювані імпорт і запуск, додати короткі команди в `README.md`.

**Критерій завершення:** код у `main`, підтверджений запуск і технічні тести, без незафіксованих припущень про функції.

## Етап 2 — мобільне керування та камера

- [ ] Горизонтальний режим, лівий аналоговий джойстик ×1,25 із відступом від країв.
- [ ] Праворуч круглі кнопки дій, збільшена атака, кнопка стрибка; зручне керування одночасними дотиками.
- [ ] Реалізувати/перевірити ривок; узгодити конфлікти дій.
- [ ] Три фіксовані положення масштабу камери через UI, без pinch-зміни.
- [ ] Перевірити адаптацію різних роздільностей, мультитач, скасування дотиків та поведінку після втрати фокуса.

**Критерій завершення:** технічні тести та окреме підтвердження власником на реальному смартфоні. Усі розміри UI залишаються налаштовуваними.

## Етап 3 — автоматична Web-збірка

- [ ] Додати офіційний Godot Web-export preset, сумісний із обраним renderer.
- [ ] Налаштувати GitHub Actions та GitHub Pages після перевірки Godot-проєкту.
- [ ] Додати базову перевірку збірки й браузерного запуску.
- [ ] Надати робоче посилання та інструкцію тесту на телефоні.

**Критерій завершення:** успішна публікація саме 3D Pro, а не іншого репозиторію; фізичний смартфон — окремий тест.

## Етап 4 — базовий ігровий цикл

- [ ] Погодити базові 3D-пропорції героя, камеру та стиль low-poly; перевірити продуктивність.
- [ ] Створити одну компактну локацію з взаємодіями, супротивником і простим боєм.
- [ ] Реалізувати в мінімальному обсязі HP/MP, бойовий стан, регенерацію та медитацію.
- [ ] Протестувати розвиток, енергію, рівні, характеристики й матеріальний навик **без передчасного затвердження балансу**.

## Етап 5 — підготовка мережевої MMORPG

- [ ] Створити окреме ТЗ на авторитетний сервер і протокол синхронізації.
- [ ] Перевірити двох клієнтів, відключення/перепідключення, реплікацію та AOI на малій локації.
- [ ] Спроєктувати транзакційне збереження акаунтів, персонажа, предметів та енергії.
- [ ] Поступово розвивати світ, економіку, майстерність зброї, ранги, смерть і переродження відповідно до [GAME_CONCEPT.md](GAME_CONCEPT.md).

## Порядок і правила

- Один етап не означає автоматичної реалізації всіх його пунктів; обсяг кожного завдання погоджується окремо.
- Статус «виконано» ставити лише після перевірок, коміту і за потреби оцінки власником.
- Бажаний порядок: працездатний прототип → мобільний тест → Web-публікація → невеликий ігровий цикл → мережева інфраструктура.
- Відкриті рішення: точна камера, масштаб 3D-персонажа, характеристики ривка й бою, renderer, мобільна продуктивність, серверний стек і баланс.
